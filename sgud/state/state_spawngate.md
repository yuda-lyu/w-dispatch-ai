## 三、已知待辦

- **spawnGate／quotaGate 待辦(da67)**:①claude／codex 真實派工與 agy 之 CPU 占用未測(會耗訂閱額度／本機無 agy 行程),故三家預設不限;有授權時以真實派工量測再決定是否預設限制;②非 Windows 之 `ps` 路徑只以夾具測、未實機驗;③`execCli` 自理之非驗證失敗重試不重新守門(要完整須逐次呼叫 `execCli` 並複製其不重試判準,同 `runExecCli.mjs` 檔頭既有已知差異);④預約為保守估計(放行後 `settleMs` 內他個行程結束,空出之名額至多晚 `settleMs` 才被取用),要消除須追蹤 PID 或「本行程呼叫結束即喚醒等待者」;⑤`quotaGate` 對 `rate-limited` 狀態字與撞限後實際恢復時刻仍未實測(只見過 `ok`);⑥全域技能 `dispatch-*` 文字由主控同步(見 `agent-out/da67-修正報告.md`〈七〉);⑦`WDispatchAi` 未匯出 `cliSpawnGate`(內部模組),若要讓呼叫端自行對非 w-dispatch-ai 之 spawn 守門須另案.
- **minGapMs／暫時性重試待辦(da320,Gitea #85)**:①回報之 `Error: Unexpected error database is locked` 字樣在本機未重現(僅冷資料庫建表競爭〔另一種訊息〕),**預設 1500 ms 與重試辨識皆未經對原現象之直接驗證**;待提出端以實際工作負載觀察(提案驗證 §3-3),若仍見失敗請附完整 `stderr`／`stdout` 與同時啟動之行程數,據以調整預設或增辨識字樣;②「近同時啟動」是否因錯開而避免失敗,僅有冷資料庫 3 個實例相隔 1500 ms 全成功 1 批(樣本小),已就緒資料庫與真模型執行中之競爭無法量測(免費池當日不可用);③冷資料庫 `Failed query: CREATE TABLE …` 形狀目前不納入重試辨識(待裁示:是否增為第二字樣);④N 個併發最後一個多等約 (N−1)×1.5 秒。
